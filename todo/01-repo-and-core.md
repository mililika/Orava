**Goal:** turn the repo into an npm workspaces monorepo and move the pure domain engine into
`packages/core`, so the server (section 02 onwards) and the web app compute the same Money
health report. Also clean up what the hackathon left behind. The app must look and behave exactly
as before when this section is done.

**Depends on:** nothing.

## Target layout

```
/
  package.json            workspaces: ["apps/*", "packages/*"]; root scripts
  apps/
    web/                  the Expo app, moved from mobile/ (git mv, keep history)
    server/               created in section 02
  packages/

    contracts/            @orava/contracts: zod schemas + inferred types for the API
```

The hackathon's `db/` and `docs/` folders are gone. The database lives in Supabase and isn't
defined by any file in the repo; its schema is written out in section 03.

### `@orava/core`

Create `packages/core` (TypeScript, `strict`).

**How shared packages are built** (applies to `core` and `contracts`): NestJS compiles to
CommonJS and relies on decorator metadata, so the server can't load another package's `.ts`
sources at runtime (and esbuild-based runners like `tsx` don't emit decorator metadata). So each
shared package is **compiled to JS** with `tsup` into `dist/`, as both ESM and CJS with `.d.ts`
files, and its `package.json` `exports` map `types`, `import` and `require` to those files.
Metro (web) and Nest (server) both consume `dist/`.
- `npm run build` at the root builds the packages first (`npm run build -w packages/core -w
  packages/contracts`), then the apps.
- The root dev scripts run `tsup --watch` for the packages alongside the web app or server, so
  changes in a package show up without a manual rebuild.
- If the current Expo docs show a cleaner way for Metro to read package sources directly (for
  example a custom export condition), that's fine for the web side, but the server always uses
  `dist/`.
